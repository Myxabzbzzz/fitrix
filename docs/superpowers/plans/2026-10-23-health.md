# Wave 2D: Apple Health and Health Connect — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Connect Apple Health (iOS) and Health Connect (Android) so sleep, resting HR, HRV, steps, weight and other apps' workouts flow into check-in, recovery, readiness, history, load, Progress and Felix, and FITRIX workouts are written back to Health.

**Architecture:** The `health` package sits behind a `HealthSource` interface (real: `PluginHealthSource`; tests: `FakeHealthSource`) exposed by `healthSourceProvider`, like `LocationSource` / `Speaker`. Pure math (`health_math.dart`) decides the sleep night, baselines, readiness factors, sport mapping, deterministic ids and dedupe. A `HealthSync` notifier reads on connect / app start / resume (throttled) into a local per-day cache (`HealthDailyStore`, not synced) and imports weight and workouts into the existing stores; imported workouts are ordinary `CompletedWorkout`s plus a `health_import` document. A listener writes newly saved FITRIX workouts to Health.

**Tech Stack:** Flutter 3, Riverpod 2, go_router, new `health` ^13.3.2, `uuid` (v5), shared_preferences; Node backend; Supabase Postgres + pgTAP.

**Spec:** `docs/superpowers/specs/2026-10-23-health-design.md`

- Never request Health permissions before the user taps Connect. Every `HealthSource` call is wrapped: an exception (locked phone "Protected health data is inaccessible", missing Health Connect, denied type) yields "no data", never a crash or a blocked screen.
- Spec values: baseline = mean of previous ≤ 28 days excluding today, needs ≥ 5 values, else no factor. Resting HR ≥ +5 bpm → −6, ≥ +8 → −10. HRV ≤ −10 % → −6, ≤ −20 % → −10, ≥ +10 % → +3. HRV kinds `sdnn` (iOS) and `rmssd` (Android) never mixed. Read throttle 15 minutes. First read 30 days back.
- Sport mapping: running→running; cycling/biking (incl. indoor/stationary)→cycling; soccer→football; downhill skiing, cross-country skiing, snowboarding, skating→winterSports; traditional/functional strength, weightlifting→gym; any other→fitness.

Skip records whose `sourceId` is FITRIX's own bundle / package id (`com.elibayev.fitrix`). Skip a record overlapping a FITRIX workout of the same sport by > 50 % of the record's duration.
- New `user_documents` kind `health_import` (doc id = completed workout id). Daily health values are local only (not synced).
- Brand names (Apple Health, Health Connect, Apple Watch, Garmin, WHOOP, Strava, Mi Band, Zepp, Mi Fitness) are not translated. All other new text in en/ru/uz/es (Uzbek ‘ U+2018), `flutter gen-l10n`, generated files committed, never hand-edited. Honesty: no copy promising features not built.

## Review Focus

- A FITRIX workout written to Health and then read back is not imported (source id), and a watch recording of a workout the user also logged in FITRIX is not counted twice (overlap rule). Tests in Task 7.
- Health throws (locked phone, denied, missing Health Connect) during any read: the app keeps yesterday's cache and shows nothing new, without a crash or a snack storm. Tests in Task 4.
- A denied type is "unknown", not zero: no "0 steps" or "0 h sleep" shown, and the check-in slider keeps its default. Tests in Task 4 and Task 6.
- Sleep: a 23:30–07:10 night counts for today; a 14:00 nap does not; two segments of one night (woke at 03:00) are summed; in-bed/awake time is not sleep. Tests in Task 3.
- A deleted imported workout never comes back on the next read or from another device, and the same Health record read on two devices produces one workout. Tests in Task 7.
